📋 REGLAS DE AUDITORÍA IMPLEMENTADAS
REGLA #1: No usar localStorage en entornos sandboxed
Problema: localStorage no está disponible en iframes sandboxed sin flag allow-same-origin.
Solución: Usar variables JavaScript o estado en memoria para almacenamiento temporal.
// Antes (❌ Error)
localStorage.setItem('data', value);

// Después (✅ Correcto)
const appState = { data: value };
REGLA #2: Validar disponibilidad de APIs del navegador
Problema: Asumir que todas las APIs están disponibles causa crashes.
Solución: Implementar detección y fallbacks para APIs restringidas.
function isStorageAvailable() {
  try {
    localStorage.setItem('test', 'test');
    localStorage.removeItem('test');
    return true;
  } catch(e) { return false; }
}
REGLA #3: Manejo graceful de errores
Problema: Errores no capturados rompen la aplicación.
Solución: Implementar try-catch y logging de errores.
try {
  // Código potencialmente problemático
} catch (error) {
  console.error('Error capturado:', error);
  // Continuar con flujo alternativo
}
REGLA #4: Todas las zonas clickeables deben ser funcionales
Problema: Botones sin event listeners crean confusión.
Solución: Validar que todos los elementos interactivos tengan funcionalidad.
document.querySelectorAll('.btn').forEach(btn => {
  if (!btn.onclick && !btn.hasEventListener) {
    console.warn('Botón sin funcionalidad:', btn);
  }
});
REGLA #5: Testing de funcionalidad en sandbox
Problema: Código funciona localmente pero falla en producción.
Solución: Testear siempre en entorno sandbox similar al de producción.
// Crear sandbox local para testing
<iframe sandbox="allow-scripts"></iframe>
// Validar funcionalidad antes de deploy
