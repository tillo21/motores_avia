## REGLA UNIVERSAL POEGUARD — Protocolo Anti-Desconexion v1.0 ## Integrado en: Libro Blanco AVIA | Reglas LB-POE-017..022 ### CONTEXTO Esta app se ejecuta como Canvas App en un iframe de Poe (poe.com). El API window.Poe se inyecta desde el frame padre. La inyeccion puede retrasarse. La conexion puede perderse. El codigo DEBE ser resiliente. ### MANDAMIENTOS (NUNCA violar): 1. NUNCA hacer check sincrono unico de window.Poe al cargar. SIEMPRE usar waitForPoe(timeout) con polling asincrono cada 200ms. 2. NUNCA sobrescribir window.Poe con un stub/mock falso. SIEMPRE usar un flag PoeReady y funciones wrapper. 3. NUNCA llamar window.Poe.sendUserMessage() directamente. SIEMPRE usar poeSend(msg, opts, retries) que verifica conexion + reintenta 3 veces con backoff exponencial (2s, 4s, 8s). 4. NUNCA llamar window.Poe.registerHandler() directamente. SIEMPRE usar poeRegisterHandler(name, func) que encola handlers si Poe no esta listo y los registra con flushHandlerQueue() cuando la conexion se establece. 5. NUNCA dejar al usuario sin feedback de conexion. SIEMPRE mostrar banner sticky rojo con boton "Reintentar" cuando la conexion falla. Ocultar al reconectar. 6. NUNCA asumir que la conexion es permanente. SIEMPRE tener auto-recovery (setInterval 10s) que detecta si window.Poe aparece tardio y reconecta transparentemente. ### ERRORES QUE NO SE DEBEN REINTENTAR: - USER_REJECTED_CONFIRMATION (usuario cancelo) - ANOTHER_CONFIRMATION_IS_OPEN (modal activo) - INVALID_INPUT (parametros incorrectos) ### FLUJO DE CADA LLAMADA API: poeSend() → isPoeReallyAvailable()? → SI → sendUserMessage() → exito/retry con backoff NO → waitForPoe(5s) → conecta? → retry / banner+error ### CHECKLIST PARA NUEVAS FEATURES: [ ] Usa poeSend() en vez de window.Poe.sendUserMessage()? [ ] Usa poeRegisterHandler() en vez de window.Poe.registerHandler()? [ ] Tiene try/catch con mensaje de error en espanol? [ ] Tiene feedback visual (loading spinner) antes de la llamada? [ ] Devuelve creditos al usuario si falla (si aplica)? [ ] Muestra error especifico del bot (statusText)? ### INTEGRACION CON OTROS PROTOCOLOS: - Cost Shield: poeSend() + useCredits() = refund automatico en catch - ErrorGuard: window.onerror captura errores no manejados - Merkle: merkleCommit() solo tras respuesta exitosa - Persistencia: idbSave() preserva estado entre reconexiones - Atomic Design: banner es componente atomico reutilizable
