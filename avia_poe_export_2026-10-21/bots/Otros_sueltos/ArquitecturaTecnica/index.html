🔄 Flujo de Datos: Notificación Push End-to-End
1️⃣ Evento Generado
Backend service detecta evento (ej: nuevo mensaje, alerta sistema, tarea completada)
2️⃣ Encolado en RabbitMQ
Evento se serializa y encola en RabbitMQ para procesamiento asíncrono y garantía de entrega
3️⃣ Procesamiento por Notification Service
Worker consume evento, aplica reglas de negocio, renderiza template, verifica permisos
4️⃣ Persistencia en PostgreSQL
Notificación se guarda en BD para historial, auditoría y recuperación ante fallos
5️⃣ Publicación en Redis PubSub
Notificación se publica en canal Redis para distribución a todos los servidores WebSocket
6️⃣ Emisión via WebSocket
Gateway WebSocket recibe desde Redis y emite a cliente conectado en tiempo real
7️⃣ Renderizado en Cliente
Cliente React recibe WebSocket message, actualiza estado y renderiza Toast notification

⚠️ DDoS Protection

Handshake WebSocket: Cliente envía JWT en query param o header durante conexión inicial. Gateway valida token, extrae user_id, y asocia socket a usuario. Todas las notificaciones se filtran por user_id para garantizar privacidad.

📈 Estrategia de Escalabilidad

🔄 Escalado Horizontal

  • Múltiples instancias WebSocket Gateway
  • Load balancer con sticky sessions
  • Redis PubSub para sincronización
  • Stateless architecture

💾 Persistencia Eficiente

  • PostgreSQL para datos históricos
  • Redis cache para notificaciones recientes
  • Archivado automático a S3 (>30 días)
  • Índices optimizados (user_id, created_at)

🔧 Redundancia

  • PostgreSQL: Replicación master-slave
  • Redis: Sentinel para HA
  • RabbitMQ: Cluster de 3 nodos
  • Multi-AZ deployment en cloud
