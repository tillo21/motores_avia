1. 🎯 Overview del Sistema

AVIA NOMADA Backend v6.2 es un ecosistema de inteligencia distribuida diseñado para orquestar decisiones consensuadas entre múltiples agentes especializados (AVIAs) mediante un algoritmo de Byzantine Fault Tolerance (BFT) adaptado.

Características Principales

🗳️ Consenso BFT Votación ponderada entre 8 AVIAs con umbral del 75%
🧠 Grafos LEID Estructuras semánticas Design Atomic en Neo4j
⚡ Async/Await FastAPI + Uvicorn con alto rendimiento
💾 Triple Store Neo4j (grafos) + Redis (cache) + MongoDB (opcional)
🤖 Multi-LLM Integración OpenAI GPT-4 & Anthropic Claude
🔒 Security First JWT, OAuth2, rate limiting, CORS configurado
📊 Trazabilidad Evidencias vinculadas, versiones, auditabilidad
🐳 Docker Ready Stack completo con docker-compose

Principios Metodológicos

  • AMS v4.0: AVIA Methodology Specification
  • Design Atomic: Átomo → Molécula → Célula → Tejido → Órgano → Organismo → Ecosistema → Constelación
  • LEID: Lectura, Escritura, Inclusión, Desarrollo
  • Hegemonía Semántica del Español: Código, comentarios y documentación en español
  • AVIA-Pukkart: Trazabilidad y autenticidad de entregables

Flujo de Consenso

1. POST /api/v1/consensus
   ↓
2. Validar proposición (Pydantic)
   ↓
3. Distribuir a AVIAs relevantes
   ↓
4. Ejecución paralela de votación (asyncio.gather)
   ↓
5. Cada AVIA:
   - Evalúa relevancia (capabilities)
   - Si relevante: LLM genera reasoning
   - Emite voto: APPROVE / REJECT / ABSTAIN
   ↓
6. Calcular consenso ponderado
   ↓
7. Si ≥75%: APPROVED, sino: REJECTED
   ↓
8. Persistir en Neo4j (background task)
   ↓
9. Cache en Redis (TTL 24h)
   ↓
10. Retornar ConsensusResult + graph URI

Flujo de Construcción de Grafos LEID

1. POST /api/v1/graphs/leid
   ↓
2. Validar estructura Design Atomic
   ↓
3. Generar graph_id único
   ↓
4. Crear meta-nodo Graph en Neo4j
   ↓
5. Batch insert de nodos (UNWIND)
   - Aplicar labels dinámicos
   - Incluir leid_level
   ↓
6. Batch insert de relaciones
   - Relaciones tipadas (CONTAINS, DERIVES_FROM, etc.)
   ↓
7. Indexar por graph_id
   ↓
8. Retornar URI: neo4j://graphs/leid/{graph_id}
   ↓
9. Permitir exportación:
   - GET /graphs/{id}/export?format=json_ld
   - Soporta: RDF/XML, Turtle, Cypher

6. ⚙️ Services & Business Logic

ConsensusEngine

Responsabilidad: Orquestar votaciones BFT entre AVIAs

  • ✅ Evaluación de relevancia por capabilities
  • ✅ Ejecución paralela con asyncio.gather
  • ✅ Timeout configurable (30s default)
  • ✅ Generación de reasoning con LLMs
  • ✅ Cálculo de consenso ponderado
  • ✅ Persistencia en Neo4j + cache Redis
# Uso básico
engine = ConsensusEngine()

votes = await engine.run_voting(
    consensus_id="consensus-123",
    proposition={"title": "...", "category": "technical_decision"},
    avias=AVIA_CONSTELLATION
)

# Resultado: lista de votos con reasoning
# Automáticamente persistido en Neo4j

LLMProvider

Responsabilidad: Abstracción unificada de LLMs

  • ✅ Soporte OpenAI (GPT-4 Turbo)
  • ✅ Soporte Anthropic (Claude 3)
  • ✅ Fallback automático entre proveedores
  • ✅ Retry logic con exponential backoff
  • ✅ Batch generation (paralelizado)
# Uso
llm = LLMProvider()

reasoning = await llm.generate_reasoning(
    prompt="Evalúa esta proposición técnica...",
    provider="auto",  # O "openai" / "anthropic"
    max_tokens=500,
    temperature=0.7
)

# Batch processing
reasonings = await llm.batch_generate([
    "Prompt 1",
    "Prompt 2",
    "Prompt 3"
])

GraphBuilder

Responsabilidad: Construir grafos LEID en Neo4j

  • ✅ Validación Design Atomic (8 niveles)
  • ✅ Batch insert optimizado (UNWIND)
  • ✅ Labels dinámicos con APOC
  • ✅ Exportación RDF/XML, JSON-LD, Turtle
  • ✅ Inferencia de relaciones (futuro)
# Construcción de grafo
builder = GraphBuilder()

result = await builder.build_graph(
    name="Grafo Competencias LEID",
    description="...",
    nodes=[
        {"id": "lectura", "label": "Concept", "leid_level": "atomo"},
        {"id": "comprension", "label": "Concept", "leid_level": "molecula"}
    ],
    relationships=[
        {"source": "lectura", "target": "comprension", "type": "CONTAINS"}
    ]
)

# Exportar
json_ld = await builder.export_graph(result["graph_id"], format="json_ld")

Neo4j Client

Características:

  • ✅ Driver async oficial de Neo4j
  • ✅ Connection pooling (max 50 conexiones)
  • ✅ Context manager para sesiones
  • ✅ Transacciones atómicas

  • ✅ Health check con verify_connectivity()
# Uso del cliente
from app.db.neo4j_client import neo4j_driver

# Write query
result = await neo4j_driver.execute_write(
    "CREATE (n:Node {id: $id}) RETURN n",
    {"id": "node-123"}
)

# Read query
nodes = await neo4j_driver.execute_read(
    "MATCH (n:Node) RETURN n LIMIT 10"
)

# Transacción
success = await neo4j_driver.execute_transaction([
    ("CREATE (a:Node {id: 'a'})", {}),
    ("CREATE (b:Node {id: 'b'})", {}),
    ("MATCH (a), (b) CREATE (a)-[:LINKS]->(b)", {})
])

Redis Client

Características:

  • ✅ Redis async con redis-py
  • ✅ Connection pool optimizado
  • ✅ TTL automático en keys
  • ✅ Pub/Sub para WebSocket
  • ✅ Rate limiting helpers
# Uso del cliente
from app.db.redis_client import redis_client

# Cache con TTL
await redis_client.set(
    "consensus:123",
    json.dumps(data),
    ex=3600  # 1 hora
)

# Retrieve
cached = await redis_client.get("consensus:123")

# Rate limiting
count = await redis_client.incr(f"rate:{user_id}")
await redis_client.expire(f"rate:{user_id}", 60)

if count > 100:
    raise RateLimitExceeded()

@pytest.mark.asyncio
async def test_consensus_voting_weights(async_client, sample_proposition):
    """Test que pesos suman correctamente"""
    response = await async_client.post(
        "/api/v1/consensus",
        json=sample_proposition
    )
    
    data = response.json()
    votes = data["result"]["votes"]
    
    # Excluir abstenciones
    active_votes = [v for v in votes if v["vote"] != "abstain"]
    total_weight = sum(v["weight"] for v in active_votes)
    
    assert 0.8 <= total_weight <= 1.0
    assert data["result"]["approval_percentage"] <= 1.0

Dinámica de Votación

  • ✅ Cada AVIA evalúa proposiciones según sus capabilities
  • ✅ Si la proposición está fuera de su expertise, se abstiene (peso = 0)
  • ✅ Si es relevante, genera reasoning con LLM y emite voto
  • ✅ Votos: APPROVE | REJECT | ABSTAIN
  • ✅ Umbral de consenso: 75% de pesos activos
  • ✅ Timeout: 30 segundos (configurable)

architectural_design → architecture, knowledge_graphs
content_validation → writing, documentation
security_review → testing, security
ux_feedback → design, ui_ux
